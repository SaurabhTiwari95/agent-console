# Deploying to Render (free) with Google sign-in

A one-time setup, about 20 minutes. After it, every push to `main` that passes CI deploys itself.

Nothing here costs money except Claude API usage, which the console caps. Use your own accounts only.

## 0. Before you start

1. Push [cost-capped-agent](https://github.com/SaurabhTiwari95/cost-capped-agent) to GitHub and tag it
   `v0.1.0` (`git tag v0.1.0 && git push --tags`). This repo installs it from that tag.
2. Push this repo. The first CI run needs step 1 done, or the `test` and `docker` jobs can't fetch the agent.
3. **Set a monthly spend limit in the Claude Console. Do this before the first deploy.** On Render's
   free plan the console's own spend ledger is wiped on every deploy and idle spin-down (see "Things to
   know" below). That resets the daily cap, so this limit is the cap that always holds.
   1. In the [Claude Console](https://platform.claude.com/), create a workspace just for this console,
      for example `agent-console-demo`.
   2. In that workspace's limits, set a **monthly spend limit**. $5 is plenty for a demo: at the
      `AGENT_RUN_CAP_USD` of $0.10 in `render.yaml`, that is at least 50 questions a month.
   3. Create an API key **in that workspace** and use it only for this service. When the limit is
      reached, the API refuses calls from this key, the console shows the error, and nothing else you
      run is affected.

## 1. Create the Render service

1. Sign in at [render.com](https://render.com/) with GitHub.
2. **New → Blueprint**, pick this repository. Render reads `render.yaml` and proposes one free web service,
   `agent-console`.
3. It asks for the values marked `sync: false`. Fill in what you know now; you'll come back for `BASE_URL`
   and the Google values:

| Variable | Value |
|---|---|
| `BASE_URL` | `https://agent-console-xxxx.onrender.com` (the address Render shows for the service, no trailing slash) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | From step 2 below |
| `ALLOWED_EMAILS` | The Google addresses allowed in, comma-separated |
| `ANTHROPIC_API_KEY` | The key from the spend-limited workspace (step 0.3), never your main key |

`SESSION_SECRET` is generated by Render. Never copy it anywhere else.

## 2. Create the Google OAuth client

In the [Google Cloud console](https://console.cloud.google.com/), in a project of your own:

1. **APIs & Services → OAuth consent screen**: choose *External*, app name `agent-console`, your support
   email. Scopes: only `openid` and `.../auth/userinfo.email`. While the app is in *Testing*, add the same
   addresses as `ALLOWED_EMAILS` as test users.
2. **APIs & Services → Credentials → Create credentials → OAuth client ID**, type *Web application*.
   - **Authorised JavaScript origins:** none needed (the console has no JavaScript).
   - **Authorised redirect URIs:** exactly `https://agent-console-xxxx.onrender.com/auth/callback`
     (your `BASE_URL` + `/auth/callback`). For local testing with Google, add
     `http://127.0.0.1:8000/auth/callback` too.
3. Copy the client ID and secret into the Render service's environment, then **Manual Deploy** once.

The console then checks every ID token's signature, issuer (`https://accounts.google.com`), audience (your
client ID), expiry and nonce, and lets in only verified addresses on `ALLOWED_EMAILS`.

## 3. Connect CI to Render

1. In the Render service: **Settings → Deploy Hook**, copy the URL. Treat it like a password: anyone with it
   can trigger deploys.
2. In GitHub: **Settings → Secrets and variables → Actions → New repository secret**,
   name `RENDER_DEPLOY_HOOK_URL`, paste the URL.

From now on the CI `deploy` job runs on pushes to `main`, only after `security`, `test`, `docker` and
`docs` all pass, and calls the hook. Without the secret it prints a notice and skips, so forks and early
pushes stay green. Render's own auto-deploy is off in `render.yaml`, so a red build never ships.

## 4. Check it

- `https://<your-service>.onrender.com/healthz` → `{"status":"ok"}`
- `https://<your-service>.onrender.com/readyz` → `"status":"ready"` once the sample is indexed
- Sign in with an allowed Google account; any other account gets "That account isn't allowed".

## Things to know about the free plan

- **The disk isn't persistent.** The SQLite files (questions, index, spend ledger) start empty after each
  deploy and after the service spins down when idle. The sample is re-indexed at start-up, so the console
  works, but **the daily spend cap restarts with the ledger**. That is why step 0.3 is required: the
  workspace's monthly spend limit in the Claude Console always holds, and the per-run cap still holds
  within each run. If you ever need the daily cap to survive restarts, a paid persistent disk mounted
  at `/data` does it, with no code change.
- Free services sleep after a period without traffic; the first request after that takes a while.
- One instance only: the background runs, rate limits and SQLite live in the one process
  (see README, "How it scales").

## Secrets, in one place

| Secret | Lives in | Never in |
|---|---|---|
| `SESSION_SECRET` | Render (generated) | git, logs, chat |
| `GOOGLE_CLIENT_SECRET` | Render | git, CI |
| `ANTHROPIC_API_KEY` | Render (and your shell for local real-Claude runs) | git, CI, `.env.example` |
| `RENDER_DEPLOY_HOOK_URL` | GitHub Actions secret | git, logs |
| `BLOCKED_WORDS` | GitHub Actions secret (pre-publish scan) | git |
